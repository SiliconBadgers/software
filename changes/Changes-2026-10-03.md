## Corrections found while doing this

- **Vocabulary head "124,160 ops/byte" was misleading.** Boundary bytes count only edges between scheduled ops,
  so weights are excluded. The head reads the 417,177,600-byte tied embedding each decode step; including it
  gives 2.4 ops/byte. `offload.py` now reports leaf-input bytes (weights, caches and graph inputs read by the group,
  once per tensor) and ops per boundary+leaf byte next to the old ratio. The text no longer calls either ratio an
  arithmetic intensity against memory traffic. New test: `core/tests/test_offload.py`.
- **"Ranking checked against every other prompt" was not done by the code.** It is now computed. The top-3 groups
  by measured share match the representative prompt in 5 of 8 prompts for prefill and 4 of 8 for decode; the
  write-up names the ones that differ.
- **`pp8192` graphs were added to the run folder after the run** and are not in its manifest; the exact
  command was not recorded. Now stated in the write-up and in `EVIDENCE.md`. The experiment JSON change that adds
  8192 to `graphs.prompt_lengths` is committed so a new run captures them itself.
- The pp8192 "no measured share" note blamed the timing-exclusion policy; the actual reason is that no traced
  8192 run exists (opt-in diagnostic, not run). Reworded.

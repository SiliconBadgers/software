# Changes - 2026-10-06

Optional CUDA execution for faster software experimentation. CPU remains the default and current
trace/graph reference. This does not change the accelerator-modeling objective or establish a permanent
cross-backend validation policy.

- `--cuda only` runs CUDA timing without CPU timing, operation traces, graph capture or per-prompt stages.
- Ordinary `--cuda on` runs the separately built CPU reference and CUDA, not CUDA-build CPU controls.
- `--cuda-controls` and `--cuda-no-host-control` are explicit diagnostic options for reference mismatches
  and host-buffer/repacking investigations. Control-specific ratios/checks are opt-in.
- Both harnesses report observed model-buffer placement separately from requested GPU layers. Capture
  rejects CPU fallback; reanalysis labels it explicitly and excludes it from accelerated speedups.
- The shared reader preserves role/build identity, including historical controls and unknown builds,
  across validation, plots, prompt summaries and the dashboard. CPU instrumentation and graph capture
  stay on their separate CPU build. CI includes the core tests.
- Full benchmark packages and detailed diagnostic notes are preserved separately, outside the proposed
  merge. Quantified speedup claims and unrelated web-maintenance changes are excluded from this PR.

See [the concise verification note](../docs/cuda-verification.md) for commands, checks and limitations.
The existing recorded experiments and archived dashboard graph payload are unchanged.

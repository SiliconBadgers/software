## 1. What this commit does, in one paragraph

It adds a redesigned, cross-platform profiling setup: shared code in `core/`, per-OS entry points in `unix/`
(Linux and macOS) and `windows/`, and a shared `results/` folder with one folder per run named
`<date>_<HHMM>_<os>`. One command (`profile`) builds the pinned llama.cpp, runs the timing baselines and CPU
operation traces, captures the scheduled dataflow ("control flow") graph of the model, runs eight different
prompts, and writes summaries, checks, figures and a `run-manifest.json`. It also adds per-prompt timings and
traces, and an option for longer continuations with a decode-cost-versus-context curve.

## 6. Problems found and fixed on the way

1. **Line endings.** Git for Windows checks files out as CRLF. That would break the trace patch (it would not
   apply to an LF llama.cpp checkout) and `.sh` scripts. Fix: `.gitattributes` forcing LF in the new folders;
   the runner forces `core.autocrlf=false` on the llama.cpp checkout and normalizes the patch to LF.
2. **Resource compiler.** CMake with clang on Windows needs `rc.exe`; it was not on PATH. Fix: the Windows
   profile searches the Windows SDK (newest version) and LLVM's `llvm-rc`.
3. **Backslash paths in CMake options** were read as escapes (`\P`). Fix: every path option is passed with
   forward slashes.
4. **Wrong tools in the manifest** (system CMake 3.29 instead of the venv's 4.4.3, no ninja). Fixed.
5. **A brace bug in `profile.cpp`.** The file had been reformatted outside our tools (most likely an editor auto-format) and one brace in `logits()` had moved, so the logits
   file would have been rewritten 248,320 times per checkpoint. Restored, and a test now pins the program text to
   the 09-22 original (it flags this exact edit).
6. **Trace patch leaked into the "pristine" baseline.** The patched source and the baseline build shared one
   checkout, so rebuilding the baseline compiled the trace code into it (confirmed: the baseline DLL contained
   the trace marker). Fix: the traced build uses its own git worktree (`work/llama.cpp-profile`); each build is
   now checked for the trace code (absent in the baseline, present in the traced build) and the result is
   recorded in the manifest. Also, the baseline build is now always run incrementally, so harness edits are
   picked up (previously an existing executable was reused).
7. **OpenMP** is requested by llama.cpp but is not found on this toolchain, so it is not used. Recorded in each
   manifest under `build.effective`.
8. **An unclosed file** in `ops.aggregate` (a leftover of the original script) is fixed by streaming.
9. A dry run printed `git init` for an existing checkout; fixed. A few empty folders were briefly created under
   `experiments/` by mistake and removed immediately (nothing tracked was touched).

## 8. Exactly what this commit profiles

**Model:** Qwen3.5-2B, Unsloth GGUF `Qwen3.5-2B-Q4_K_M.gguf` (repository `unsloth/Qwen3.5-2B-GGUF`, revision
`f6d5376be1edb4d416d56da11e5397a961aca8ae`, 1,280,835,840 bytes, SHA256
`aaf42c8b7c3cab2bf3d69c355048d4a0ee9973d48f16c731c0520ee914699223`). Mixed quantization (Q4_K, Q5_K, Q6_K, Q8_0,
F32); **not** the proposed custom INT4/group-64 format.
**Runtime:** llama.cpp commit `f46bc30cb6a7f68a67e34a00061e20a4ad1eff43`, Release build, `GGML_NATIVE=ON`, shared
libraries, CPU backend (Metal is available only on macOS/arm64 and has not been exercised).
**Configuration:** one sequence, flash attention on, micro-batch at most 512 tokens, 6 threads by default.

### Commands (Windows PowerShell, from the repository root)

```powershell
# 1. Preflight: checks tools, fetches the pinned llama.cpp, tests the trace patch, configures CMake.
#    No model download, no compile. Creates .venv on first use.
windows\run.ps1 doctor

# 2. Show every command a run would execute, without running or writing anything.
windows\run.ps1 profile --dry-run

# 3. Smoke run: 128-token prompt, 1 repetition, 8 decode steps, W1+W2+W3.
#    First time: downloads the model and compiles llama.cpp twice (baseline and traced).
windows\run.ps1 profile --smoke

# 4. A first real run (skips the slow 8192-token case).
windows\run.ps1 profile --lengths 128 512 2048

# 5. The full default run: W1 (128/512/2048/8192), W2, W3, W4, W5, then analysis.
windows\run.ps1 profile

# 6. Only the per-prompt stages (W4 graphs and W5 timings/traces for the eight prompts).
windows\run.ps1 profile --prompts-only

# 7. Longer continuations (W6): 256 steps, or choose the number. Skipping traces keeps it small and fast.
windows\run.ps1 profile --lengths 128 2048 --long-continuation --no-trace --no-graphs --no-prompt-graphs --no-prompt-timings
windows\run.ps1 profile --lengths 128 512 --decode-steps 512 --no-trace --no-graphs --no-prompt-graphs --no-prompt-timings

# 8. Redo the analysis and rebuild the graph reports/SVGs of an existing run (raw files are only read).
windows\run.ps1 analyze results\<run folder>
```

If PowerShell blocks the script, prefix any command as
`powershell -NoProfile -ExecutionPolicy Bypass -File windows\run.ps1 <arguments>`.

Useful flags: `--lengths`, `--threads`, `--repetitions`, `--trace-repetitions`, `--decode-steps`,
`--long-continuation`, `--skip-metal`, `--no-trace`, `--no-graphs`, `--no-prompt-graphs`,
`--no-prompt-timings`, `--include-diagnostic`, `--prompt-set FILE`, `--model PATH`, `--work-dir DIR`, `--smoke`,
`--dry-run`. Fixed-length runs need `length + steps <= 9500`; the command stops early with the maximum if not.

**Linux and macOS** (untested): the same commands with `unix/run.sh` instead of `windows\run.ps1`, from the
repository root, e.g. `unix/run.sh doctor`. On a Mac with Apple Silicon the Metal backend is offered
automatically; `--skip-metal` turns it off.

### What you get

A new folder `results/<YYYY-MM-DD>_<HHMM>_<windows|macos|linux>/` (never reused). Main contents:
`run-manifest.json` (host, tool versions, pins, build settings, command, status `complete`), the raw timing files
(`cpu-baseline*.jsonl`, saved logits, `cpu-op-trace.jsonl.gz`), `analysis/` (`summary.json`,
`operation-summary.json`, validation JSONs, `profiling-summary.png/.pdf`, `decode-curve.*`),
`graphs/` (one folder per graph plus `prompt-comparison.md`), `prompts/<id>/` and `prompt-profiles.json`. Check
that the manifest says `"status": "complete"`, and that `analysis.profile_bit_identical` is `true`.

Measured run times on this machine (from the run manifests): the first smoke run took 4.6 minutes **including** the
model download and both compiles of llama.cpp; the second smoke run 2.7 minutes; the 16 prompt-graph captures 3.0
minutes. Other durations have not been measured.
Results from different machines are not comparable to each other or to the recorded Apple M5 Pro baseline.

# Changes - 2026-10-05

Optional CUDA execution and a matched CPU/CUDA benchmark for the software profiling harness. This work supports
faster experimental iteration while keeping CPU-only execution as the default and CPU traces/graphs as the
canonical architecture evidence.

AI assistance (per `AGENTS.md`): OpenAI Codex, model `gpt-5.6-sol`.

## Implementation

- Added explicit `profile --cuda off|on|only`; the default is `off`. `only` is a true fast path that runs CUDA
  timing without CPU timing, traces, graph capture or per-prompt stages.
- Split canonical CPU and CUDA-enabled binaries. Comparison mode records canonical CPU, a zero-offload CPU
  control from the CUDA build, and CUDA separately. The trace validates against canonical CPU; graph capture
  also uses that canonical build.
- Added CUDA timing rows to fixed-length and per-prompt analyses, plots, manifests and numerical saved-logit
  checks. No CUDA behavior is interpreted as accelerator-architecture evidence.
- Added best-effort CUDA compiler and GPU provenance to the run manifest.
- Kept Windows setup process-local: the wrapper imports the installed Visual Studio developer environment when
  standalone LLVM is absent and discovers an already installed CUDA toolkit without changing persistent PATH.
- Added synthetic tests for opt-in backend selection, CUDA logit comparisons, per-prompt summaries, provenance
  omission, and toolkit discovery.

## Measured result

[`../results/2026-10-05_0954_windows/EVIDENCE.md`](../results/2026-10-05_0954_windows/EVIDENCE.md) records the
matched benchmark. On the measured RTX 5070 Ti host, CUDA improved prefill throughput by 49.03x to 97.94x for
the primary 128/512/2048-token cases and decode throughput by 8.44x to 8.54x. All CPU/CUDA checkpoints were
finite and selected the same top token. The result supports rapid CUDA candidate evaluation followed by
canonical CPU-reference confirmation; it does not accelerate analytical graph sweeps or establish hardware
architecture conclusions.

## Validation and boundary checks

- Repeated CPU execution in the CUDA-enabled binary reproduced all six saved checkpoints byte-for-byte; timing
  was within 0.4–2.0% of the recorded run.
- A separate CPU-only build exposed a real build-configuration effect: its prefill and decode timings differed
  from the CUDA-enabled binary and its checkpoints were close but not byte-identical. Documentation therefore
  prohibits comparing this run's CPU row with historical/separately compiled CPU baselines.
- A pre-split `profile --cuda on --smoke` reproduced the expected validation failure when the CUDA-build CPU
  baseline was compared bit-for-bit with the CPU-only traced build. The split-build comparison mode fixes that
  invariant: canonical CPU baseline versus canonical CPU trace, with CUDA-build CPU kept as a distinct control.
- A real split-build comparison smoke completed with two of two canonical CPU/profile checkpoints bit-identical;
  a warm cached `--cuda only --smoke` completed end to end in 6.06 seconds without running any CPU case.
- Regenerated and visually inspected both the historical two-role and new three-role profiling figures. Title,
  provenance, legends, annotations, axes and footers do not overlap; the historical CPU curve is explicitly
  labeled as the CUDA-build control rather than the canonical CPU-only reference.
- The existing immutable 2026-09-22 regression fixtures remain unchanged; the full validation commands and
  final results are recorded in the pull request.

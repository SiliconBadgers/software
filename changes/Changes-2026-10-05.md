# Changes - 2026-10-05

Optional CUDA execution and a matched CPU/CUDA benchmark for the software profiling harness. This work supports
faster experimental iteration while keeping CPU-only execution as the default and CPU traces/graphs as the
current architecture-evidence path.

AI assistance (per `AGENTS.md`): OpenAI Codex, model `gpt-5.6-sol`.

## Implementation

- Added explicit `profile --cuda off|on|only`; the default is `off`. `only` is a true fast path that runs CUDA
  timing without CPU timing, traces, graph capture or per-prompt stages.
- Split the current CPU-reference and CUDA-enabled binaries. Comparison mode records the CPU reference, a
  zero-offload CPU control from the CUDA build, and CUDA separately. The trace validates against that CPU
  reference; graph capture also uses that CPU-reference build.
- Added CUDA timing rows to fixed-length and per-prompt analyses, plots, manifests and numerical saved-logit
  checks. No CUDA behavior is interpreted as accelerator-architecture evidence.
- Added best-effort CUDA compiler and GPU provenance to the run manifest.
- Kept Windows setup process-local: the wrapper imports the installed Visual Studio developer environment when
  standalone LLVM is absent and discovers an already installed CUDA toolkit without changing persistent PATH.
- Added synthetic tests for opt-in backend selection, CUDA logit comparisons, per-prompt summaries, provenance
  omission, and toolkit discovery.

## Measured result

[`../results/2026-10-05_2035_windows/EVIDENCE.md`](../results/2026-10-05_2035_windows/EVIDENCE.md) records the
split-build matched benchmark. On the measured RTX 5070 Ti host, CUDA improved prefill throughput by 46.73x to
98.81x for the primary 128/512/2048-token cases and decode throughput by 8.53x to 8.85x. All CPU/CUDA checkpoints were
finite and selected the same top token. The result supports rapid CUDA candidate evaluation followed by
checks against the current CPU reference; it does not accelerate analytical graph sweeps or establish hardware
architecture conclusions.

## Validation and boundary checks

- The committed split-build run records CPU reference, CUDA-build CPU control and CUDA execution separately in
  filenames, `config.backends`, and independent build-manifest sections.
- The CPU-only and CUDA-enabled builds expose a real build-configuration effect: the CUDA-build CPU control has
  20.6-22.2% lower prefill throughput and 7.7-9.9% higher decode throughput than the CPU-only reference across
  primary cases. The matched speedup therefore uses the CUDA-build CPU control.
- Prefill exposes parallel matrix work across prompt tokens and amortizes GPU launch overhead; batch-one decode
  remains dependency-ordered and more exposed to weight movement and per-kernel latency. This explains the
  observed phase-level speedup difference without claiming a kernel-level profile.
- A pre-split `profile --cuda on --smoke` reproduced the expected validation failure when the CUDA-build CPU
  baseline was compared bit-for-bit with the CPU-only traced build. The split-build comparison mode fixes that
  invariant: current CPU reference versus its CPU trace, with CUDA-build CPU kept as a distinct control.
- A real split-build comparison smoke completed with two of two CPU-reference/profile checkpoints bit-identical;
  a warm cached `--cuda only --smoke` completed end to end in 6.06 seconds without running any CPU case.
- Regenerated and visually inspected the three-role profiling figure. Title, provenance, legends, annotations,
  axes and footer do not overlap; CPU reference, CUDA-build CPU control and CUDA are distinct.
- Browser navigation validation now waits for the saved-study view and scroll position to settle, rather than
  treating the URL hash change alone as completed navigation. This removes a reproducible Chrome timing race
  without weakening the destination or position assertions.
- Non-interactive publication authentication disables desktop credential helpers while forwarding the scoped
  request header, so a rejected local or CI request fails directly instead of opening a credentials dialog.
- The existing immutable 2026-09-22 regression fixtures remain unchanged; the full validation commands and
  final results are recorded in the pull request.

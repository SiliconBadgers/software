## Operation-sharing and offload-boundary evidence

Generated by `core/analysis/fusion.py`, `offload.py` and `compute_mapping.py` from captured graphs
and CPU op traces (no model re-run). Kept alongside its source run rather than copied here:
[`results/2026-09-27_1839_windows-2/research/compute-mapping.md`](../../results/2026-09-27_1839_windows-2/research/compute-mapping.md),
with per-graph fusion and offload tables and the graph SVGs browsable in [`results/index.html`](../../results/index.html).
What was run, what is committed and how to regenerate it:
[`EVIDENCE.md`](../../results/2026-09-27_1839_windows-2/EVIDENCE.md).

Scope: one Windows host, CPU backend only. The write-up labels each statement as **measured** (CPU
wall-clock shares), **structural** (counts and logical sizes from the captured graph) or **candidate**
(a boundary to discuss, with what would establish it). It does not establish SRAM traffic, FPGA/ASIC
stalls or the need for dedicated recurrence arithmetic.
